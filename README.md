# Список сотрудников

Тестовое задание: веб-приложение со списком сотрудников (ФИО, должность, отдел).
Регистрация/вход/выход, список только для авторизованных, поиск по ФИО, фильтр по отделу,
добавление сотрудника с валидацией, сохранение данных после перезапуска.

## Стек

- **Frontend:** React 19 + TypeScript, Vite, react-router-dom, обычный CSS (без UI-библиотек)
- **Backend:** Node.js + Express 5 + TypeScript
- **База данных:** SQLite (`better-sqlite3`), сессии также хранятся в SQLite
- **Пароли:** bcrypt (cost 10) · **Валидация:** zod · **Тесты:** Vitest + Supertest

## Требования

- Node.js **22+** (версия зафиксирована в `.nvmrc`, удобно через `nvm use`)
- npm 10+

## Быстрый старт (dev-режим)

```bash
npm install
npm run dev
```

Откройте **http://localhost:5173**.
Vite отдаёт frontend и проксирует `/api` на Express (http://localhost:3000) — CORS не нужен.

## Production-режим (один сервер)

```bash
npm install
npm run build
npm start
```

Откройте **http://localhost:3000** — Express отдаёт и API, и собранный frontend.

## Сохранность данных

SQLite-файл `server/data/emplist.db` создаётся автоматически (режим WAL).
Сотрудники, пользователи и сессии переживают перезапуск приложения.
Чтобы начать с чистого листа: остановите приложение и удалите папку `server/data/`.

## API

Все ответы — JSON. Ошибки: `{ "error": "сообщение", "fields": { "поле": "сообщение" } }` (fields — при валидации).

| Метод | Путь | Описание | Авторизация |
|---|---|---|---|
| POST | `/api/auth/register` | регистрация `{ email, password }`, сразу создаёт сессию | — |
| POST | `/api/auth/login` | вход `{ email, password }` | — |
| POST | `/api/auth/logout` | выход, уничтожает сессию | — |
| GET | `/api/auth/me` | текущий пользователь | да |
| GET | `/api/employees?search=…&department=…` | список: поиск по ФИО (регистронезависимый) + фильтр по отделу | да |
| POST | `/api/employees` | добавить `{ fullName, position, department }` | да |
| GET | `/api/employees/departments` | список отделов для фильтра | да |
| GET | `/api/health` | проверка живости | — |

Отделы — фиксированный список: Разработка, QA, Дизайн, HR, Продажи.

## Ключевые решения

- **Сессии, а не JWT:** httpOnly-cookie недоступна из JS (защита от XSS-кражи), настоящий
  серверный logout, сессии переживают перезапуск благодаря SQLite-стору. При входе/регистрации
  сессия регенерируется (защита от session fixation).
- **Пароли:** bcrypt, cost 10; в БД только хеш. Лимит длины 72 символа — ограничение bcrypt.
- **Поиск по кириллице:** встроенный `LIKE` в SQLite регистронезависим только для ASCII,
  поэтому поиск идёт по колонке `full_name_lower` (JS `toLowerCase` корректно работает с Unicode).
  Символы `%`, `_`, `\` в запросе экранируются.
- **Безопасность SQL:** все запросы параметризованы.
- **Тестируемость:** `createApp(db)` принимает экземпляр БД — тесты гоняют API на `:memory:`.
